  The Solution: Preserve original PETSCII bytes throughout the entire pipeline using escape
  sequences.

  Key Changes Made:

  (0x00-0x1F) as \{XX} escape sequences where XX is the hex value

   and InputStatement.prompt from String to Vec<u8>
  3. Value Type - Changed Value::String from String to Vec<u8> to store original bytes
  4. Screen - Changed print() to accept &[u8] instead of &str, maps bytes to Unicode at print
  time using the correct PETSCII table based on current charset mode
  5. Interpreter - Updated all string functions (CHR$, ASC, VAL, LEFT$, RIGHT$, MID$) and
  string concatenation to work with byte vectors
  6. Main - Added auto-detection of .prg files by extension

  All compilation errors have been fixed, the PRG loads successfully, and the byte preservation
   system is now working. The original PETSCII bytes are preserved all the way from the PRG
  file through parsing, storage, and finally mapped to Unicode characters at print time based
